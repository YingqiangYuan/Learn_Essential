# GitHub Projects 任务管理系统使用指南

## 📋 本节目标

学完这节内容，你将能够：

- 理解看板式任务管理的核心理念
- 掌握 GitHub Projects 的基本操作流程
- 学会用 Comment 功能进行有效的异步沟通

## 🎯 为什么要学这个？

想象一下这个场景：你和同事在微信上聊任务，消息越来越多，翻了半天找不到"上次说的那个事儿"到底是什么。更糟糕的是，你以为自己做完了，对方以为你还没开始——双方信息完全不同步。

这种混乱在职场中极其常见，而 GitHub Projects 就是为了解决这个问题。

它就像一个**透明的任务看板**：所有任务一目了然，不会遗漏；谁在做什么、做到哪一步，团队成员都清楚；每个任务的讨论和交付物都集中在一个地方，不会散落在聊天记录里。

看板式项目管理（Kanban）是美国科技公司普遍使用的协作模式。无论是初创公司还是大厂，你都会遇到类似的工具——可能是 Jira、Asana、Trello，或者就是 GitHub Projects。提前熟悉这套工作流程，你入职后会更快适应。

## 📖 系统概览：理解看板的列（Column）

打开 GitHub Projects 后，你会看到一个看板界面，上面有多个列（Column），每一列代表任务的不同状态。

![github-project-kanban-workflow.png](./img/02-GitHub-Project-For-Task-Management/02-GitHub-Project-For-Task-Management-01.png)

一个典型的看板通常包含这些状态列：

| 列名 | 含义 | 谁负责 |
| --- | --- | --- |
| **Planned** | 导师规划的任务池 | 导师管理，**你不要动** |
| **Todo** | 需要你完成的任务 | 从这里选任务开始做 |
| **Doing** | 你正在做的任务 | 你拖动卡片到这里 |
| **Review** | 你已完成，等待导师审核 | 你拖动 + 留言 |
| **Done** | 导师审核通过 | 导师移动 |
| **Hold** | 暂时搁置的任务 | 导师管理 |
| **Cancelled** | 已取消的任务 | 导师管理 |
不同团队可能会根据自己的需求调整列的数量和名称，但核心逻辑是一样的：**任务从左到右流动，代表从"计划"到"完成"的全过程。而做事情的人 (你) 一般只要关注 Todo → Doing → Review 三列**

## 📖 核心工作流程

### 第 1 步：从 Todo 列选择任务

打开看板后，首先关注 **Todo** 列——这里存放的是已经分配、等待开始的任务。点击任意一个任务卡片，可以查看详细描述、截止日期、相关链接等信息。

选择任务时，考虑优先级和截止日期。如果不确定先做哪个，可以和项目负责人确认。

### 第 2 步：开始工作，拖动到 Doing

当你准备开始做某个任务时，用鼠标按住任务卡片，把它拖动到 **Doing** 列，然后松开鼠标。

这个简单的动作意义重大：它让团队所有成员都知道你正在处理这个任务，避免重复劳动，也避免"我以为你在做 / 我以为你没在做"的信息不同步问题。

### 第 3 步：完成后，拖到 Review 并留言

完成任务后，需要做两件事。

**第一，把卡片拖到 Review 列。** 操作方式和上一步一样，这表示你已经完成了工作，等待他人检查确认。

**第二，在任务下方留言（Comment）。** 点击任务卡片打开详情页，在底部找到 Comment 输入框。留言时需要包含三个要素：说明任务已完成、@ 相关审核人（输入 `` @ `` 然后选择用户名）、附上交付物链接。

一个好的留言示例是这样的：

```
@reviewer-username 我已完成这个任务。

交付物：
- 市场调研文档：https://github.com/xxx/xxx/blob/main/research.md
- 数据分析报告：https://github.com/xxx/xxx/blob/main/analysis.ipynb

```

**关键提醒：不要只甩一个链接。** 每个链接前面要简单说明这是什么，方便审核人快速理解你提交的内容。

> **INFO**
> 
> 如果实在没有明确的指示, 就直接 @ 相关审核人, 说我做完了, 或者说 Done 明确告知也行, 一定不要 move 到 Review 但什么都不说.

### 第 4 步：等待审核，任务完成

提交到 Review 后，审核人会检查你的工作。如果通过，任务会被移动到 **Done** 列。如果需要修改，审核人会在 Comment 里告诉你具体问题，你修改后重新提交即可。

提交后不需要额外通过聊天工具通知对方——这就是看板系统的优势：**审核人会定期查看 Review 列，系统也会发送通知。**

## 📖 高效协作的日常习惯

**有问题想问？** 直接在对应的任务卡片下留言，记得 @ 相关人员。把讨论集中在任务本身，而不是散落在微信或 Slack 里，这样日后回溯时能找到完整的上下文。

**每天开始工作时？** 先看看看板，了解有没有新分配的任务，检查 Review 列里有没有需要你处理的反馈。

**任务有进展时？** 及时更新任务状态。如果一个任务需要分几天完成，可以在 Comment 里记录阶段性进展，让团队了解情况。

**需要避免的做法：** 不要在聊天工具里讨论任务的具体细节，聊天记录会被新消息淹没，而 Comment 永远跟着任务走；不要提交时只甩一个链接，没有说明的链接会让审核人困惑；不要忘记更新任务状态，一个停在 Doing 列三天没动的任务，会让团队误以为你遇到了困难。

## 📱 必做：下载 GitHub 手机 App

在手机上安装 GitHub 官方 App，用你的 GitHub 账号登录，这样你就能随时随地查看和管理任务进度。

**为什么这是必做的？** 就像你每天打开手机看一眼日历，了解今天要干什么一样，随时能查看任务看板会让你的工作更有条理。有了手机 App，你可以在任何方便的时候快速浏览任务进度，不用专门打开电脑，管理起来轻松很多。

**iPhone 用户：** 打开 App Store，搜索 "GitHub"，找到官方的 GitHub App（图标是黑色背景上的白色 GitHub 猫头标志），下载并安装。

**Android 用户：** 打开 Google Play Store，搜索 "GitHub"，同样找到官方 App 下载安装。

安装完成后，打开 App，点击 **Sign in**，输入你的 GitHub 用户名和密码登录。登录成功后，你就可以在手机上查看 Projects 看板、收到任务通知、回复 Comment 了。

## 💻 可选练习：创建你的第一个看板

如果你想在正式使用前先熟悉一下操作，可以自己创建一个练习用的看板，随便玩玩，不用担心搞坏什么。

**第 1 步：创建一个 Repository**

登录 GitHub 网页版，点击右上角的 **+** 号，选择 **New repository**。给它起个名字（比如 `` my-first-project ``，名字不重要），其他设置保持默认，点击 **Create repository**。

**第 2 步：创建一个 Project**

进入你刚创建的 Repository 页面，点击顶部的 **Projects** 标签页，然后点击绿色的 **New project** 按钮。选择 **Board** 模板（看板视图），给 Project 起个名字（比如"练习看板"），点击 **Create**。

**第 3 步：创建几个任务卡片**

在看板的 **Todo** 列，点击 **+ Add item**，输入任务名称。你可以随便写几个生活中的小任务来练习，比如：「吃早饭」、「吃午饭」、「吃晚饭」、「喝杯咖啡」。

**第 4 步：体验拖动卡片**

现在试着把「吃早饭」从 **Todo** 拖到 **Doing**，再拖到 **Done**。感受一下任务状态流转的过程。你也可以点击卡片，尝试在下面写一条 Comment。

这个练习看板完全是你自己的，随便折腾，熟悉了操作之后，正式使用时就会更有信心。

## 📖 遇到问题怎么办？

GitHub Projects 的操作并不复杂，但如果你遇到任何问题，可以这样处理：

首先，截图保存问题界面，把你看到的情况记录下来。然后，把截图发给 AI 助手（比如 Claude），描述你的问题，它能解答绝大多数操作问题。如果实在解决不了，在任何一个任务下 @ 项目负责人，说明你遇到的情况。

> ⚠️🔗 **重要！和导师沟通时，一定要带上卡片链接！**
>
> 当你遇到问题想找导师帮忙时，**请不要只用文字描述"我在某某任务上遇到了问题"**——导师可能有几十张卡片在看板上，光靠文字描述根本定位不到你说的是哪一个。
>
> **正确做法：** 打开任务卡片，点击右上角的 🔗 **复制链接按钮**，把卡片的链接复制下来，发给导师。这样导师点击链接就能直接跳转到你说的那张卡片，立刻了解上下文。
>
> ❌ 错误示范："老师，我那个调研任务遇到问题了。"
>
> ✅ 正确示范："老师，我这个任务遇到问题了：https://github.com/orgs/xxx/projects/1/views/1?pane=issue&itemId=12345 具体是……"
>
> **养成这个习惯，会让你的沟通效率提升十倍。**

## 👨‍🏫 导师寄语：看板背后的职场思维

学会拖动卡片、写 Comment，这些操作本身并不难。但我想和你聊聊看板系统背后更深层的职场思维。

### "可见性"是职场协作的基石

在学校里，你的努力过程往往只有自己知道——熬夜复习、反复修改论文，这些都是"隐形劳动"。但在职场，**让你的工作进度可见，是一项核心技能。**

把任务从 Todo 拖到 Doing，看起来只是一个简单的动作，但它背后的含义是：**"我承诺开始处理这件事了。"** 把任务拖到 Review 并留言，意味着：**"我已经完成了，请检查。"**

这种"主动暴露进度"的习惯，会让你在职场中建立可靠的声誉。没有人喜欢追着问"那个事儿做得怎么样了"——当你的进度对团队透明可见，你就是那个让人放心的队友。

### 异步沟通是未来的工作方式

为什么要在任务下 Comment，而不是直接发微信问？

因为微信是"同步沟通"——你发消息，期待对方立刻回复。但在真实的工作环境中，每个人都有自己的节奏，不可能随时待命回复消息。

Comment 是"异步沟通"——你把问题或进展写在任务下面，对方在方便的时候查看和回复。这种方式：不打断别人的专注工作，所有讨论都有记录、可追溯，跨时区协作也不成问题。

在远程工作越来越普遍的今天，掌握异步沟通的能力，会让你在任何团队都如鱼得水。

### 从"被动接受任务"到"主动管理进度"

最后，我想说一个心态的转变。

很多新人把看板当作"被安排任务的地方"——导师放任务进去，我完成，就这样。但真正优秀的职场人会把看板当作**自己管理工作的工具**。

你可以主动在任务下补充笔记，记录你的思考过程；你可以在遇到阻碍时及时更新状态，让团队知道需要支援；你甚至可以主动提出新任务，放进 Backlog 等待讨论。

**看板不是监控你的工具，而是帮你展示价值的舞台。** 当你学会主动使用它，你就从"执行者"变成了"协作者"。

## 💡 关键要点总结

- **看板让协作透明。** 任务从 Todo → Doing → Review → Done 的流转，让团队所有人都清楚项目进展。
- **状态更新是一种沟通。** 拖动卡片不只是操作，更是在告诉团队"我在做什么"。
- **Comment 是任务的记忆。** 所有讨论、交付物、反馈都集中在任务下，比聊天记录更可追溯。
- **异步沟通是职场核心技能。** 学会在不打断他人的情况下高效协作，你会成为团队里最让人放心的队友。
- **主动使用看板，展示你的价值。** 它不是监控工具，而是你职业化工作方式的体现。
